## 1. 目的

同じスマホに入っている Morincum のアプリ（配当の森・不動産の森・家計の森）のデータを集めて、**インカム全体を1つの画面で見られるようにする**。

- 例：「今月は配当 ¥32,000 ＋ 家賃の手残り ¥48,000 で、合計 ¥80,000」
- 各アプリは1アプリ1役割のまま。ダッシュボードは**見るだけのアプリ**で、入力はそれぞれのアプリで行う

## 2. 決まっていること

| # | 項目 | 決定内容 | 理由 |
|---|---|---|---|
| D1 | データの置き場所 | **端末内だけ**。ユーザーのデータはサーバーに置かない | 配当の森から続く「個人の資産情報を預からない」思想を守る |
| D2 | 連携の対象 | **そのスマホに入っている Morincum のアプリ**だけ | 入っていないアプリの欄は出さない（インストールの案内だけ） |
| D3 | 形 | スマホアプリ | — |
| D4 | ダッシュボードのデータ | 受け取ったデータは、**ダッシュボード自身の端末内 SQLite** に保存する | 元のアプリを消しても、過去の推移を見られるようにする |
| D5 | 受け渡すもの | 各アプリの DB そのものではなく、**決まった形の要約（JSON）**。形は [app-link.md](app-link.md) で定める | 各アプリのデータモデルを独立させたままにする（DB 構造を変えてもダッシュボードを直さなくてよい） |
| D6 | 市場の情報 | 為替・株価・配当予想は、ダッシュボードが**バックエンドから直接取る**（`/guest/*`、`guestAuth`） | 配当の森を開かなくても、為替などの変化を反映する |
| D7 | 計算の仕方（最初） | 配当の森が計算した金額を**通貨を変えずに**受け取り、ダッシュボードは最新の為替で円に直すだけにする | 計算ロジックを2つ持たない。税引き後・NISA の計算は配当の森だけが行う |
| D8 | 計算の仕方（将来） | 配当の森の計算ロジックを共通パッケージ（`@morincum/core`、仮）に切り出し、ダッシュボードでも同じ計算をする | 株価・配当予想の更新も、配当の森を開かずに反映できるようになる |

## 3. どこまでリアルタイムか

| ケース | 反映のされ方 |
|---|---|
| 各アプリでデータを入力・編集した | **すぐ反映される**。各アプリは保存のたびに要約を書き直す（[app-link.md](app-link.md) §5） |
| 時間がたった（月が変わった・引き落とし日が来た） | **反映される**。要約には先12ヶ月分の予定も入れる |
| 為替が変わった | **反映される**。ダッシュボードがバックエンドから取る（D6・D7） |
| 株価・配当予想が変わった | 最初（D7）は、**配当の森を開いたときに反映される**。将来（D8）は、ダッシュボードだけで反映できる |

## 4. 画面のイメージ（案）

| 画面 | 内容 |
|---|---|
| ホーム | 今月のインカム合計（アプリ別の内訳）、先12ヶ月の月別棒グラフ（アプリごとに色分け）、年間合計 |
| アプリ別 | 配当の森：月別の配当予定（税引き後）／不動産の森：月別の手残り・稼働の状況 |
| 連携の状態 | 入っているアプリ、最後に要約が更新された日時、入っていないアプリのインストール案内 |

## 5. 必要な準備

| 対象 | やること |
|---|---|
| 配当の森 | 連携の書き出し（App Groups・ContentProvider・URL スキーム）を追加する版を出す。3.0.0 Tadasu か、その前の小さい版 |
| 不動産の森 | 1.0.0 Kiso に**最初から**書き出しの機能を入れる |
| 家計の森 | 後で対応する（形は [app-link.md](app-link.md) に追加する） |
| ストア・ビルド | 全アプリを**同じ Apple Developer チーム**で出し、Android は**同じ署名鍵**で署名する（EAS の同じアカウントにそろえる） |
| プライバシーポリシー | 「同じ端末にある Morincum のアプリ同士で、要約のデータを受け渡す（端末の外には出さない）」旨を各アプリに書く |
