## 7. デザインガイドライン

### 7.1 カラートークン

ファミリー共通の考え方: 基調はMORINCUMの自然系トーン、**アプリ固有のアクセント1色**で家族内の役割を区別する。不動産の森のアクセントは**テラコッタ(土・レンガ)**。

| トークン | 値 | 用途 |
|---|---|---|
| bg | #F6F4F0 | 画面背景(暖色の紙) |
| surface | #FFFFFF | カード背景 |
| border | #E6DFD4 | 罫線・区切り |
| text | #3A3229 | 基本文字(墨色) |
| muted | #8C8072 | 補助文字 |
| accent | #A8552F | アプリアクセント/出金・マイナス/CTA |
| accentSoft | #A8552F16 | アクセントの淡背景 |
| green | #4E9B58 | 入金・プラス(ファミリー共通の森の緑) |
| greenSoft | #4E9B5816 | 緑の淡背景 |
| red | #C94F4F | トラブル・警告 |
| gold | #D9962E | 更新・期日系 |
| lock | #B0A695 | ロック(有料)状態の文字 |

口座識別色(ユーザー割当・自動初期値): 例 #5B8DB8(青) / #C79A3B(アンバー)。**アクセント(テラコッタ)・緑と衝突しない色相**から割り当てる。

### 7.2 色の意味論(重要)

| 対象 | 色の使い方 |
|---|---|
| 金額の符号 | 収入・プラス=green / 支出・マイナス=accent。全画面で統一 |
| 口座 | 口座ごとの識別色。**グラフの棒・明細の色バー・見出しの■**に使用 |
| 使い分けの原則 | **「口座=バーの色、収支=金額の色」**。1画面に両方の色系が出るときも役割を混ぜない |

### 7.3 タイポグラフィ・数値表記

- 書体: システムフォント(Hiragino Sans / Noto Sans JP)
- 金額: 3桁区切り+「¥」。符号は「+/−」を明示し色と併用(色だけに依存しない)
- 手残り等の主役数字は fontWeight 800、サイズで階層をつける(32>22>16>14)
- 日付は「25日」等の和文短縮。明細行は日付を左端の固定幅で揃える

### 7.5 文言・UXライティング規約

1. **「予定」の明示**: 入出金・通知は必ず「予定」と表記。断定しない(「引き落とし予定があります」)。実際の確認は銀行口座へ誘導
2. **「削除」の追放**: ライフサイクル完了は「売却を記録」「完済を記録」「アーカイブ」。「削除」の語は訂正と完全削除(S-11)のみ
3. **「ログイン」の不使用**: アカウント・ログインの概念を出さない。連携時も機能名(バックアップと連携 等)で包む
4. **判断はユーザーに**: 「〜が必要です」ではなく「〜を上回ります。ご確認ください」。助言・推奨の表現を避ける(審査・法規対応と一貫)
5. トーン: やさしめ・自然・安心感(ブランド共通)。絵文字はアイコン代替として限定使用

### 7.6 注意事項・免責事項(設定内・常設)

6部構成: ①経営・投資判断について ②入出金の表示について ③ローンの計算について ④データの保存・管理について ⑤サブスクリプションについて ⑥税務・法律について。末尾にロゴ(無加工)+コピーライト。文言はモックS-04の実装を正とする。

⑤サブスクリプションの必須記載(ストア審査・特商法対応): - 自動更新である旨と更新タイミング(期間終了24時間前までの解約で停止) - 解約方法はストアのサブスクリプション設定(アプリ削除では解約されない) - 解約後も支払い済み期間末まで利用可。**日割り返金なし** - **返金はApple/Google各ストアの規定にもとづきストアへ申請**(開発者は個別の返金処理を行えない) - 「購入の復元」の案内(機種変更時) - 特定商取引法にもとづく表示への参照(morincum.jp)

### 7.7 ロゴ使用

- 正式表記: Morincum(モリンカム)。Morincome / Morinkamu は誤記
- ロゴ画像は**無加工で使用**(色変更・トリミング等をしない)。白背景面(カード内)に配置
- アセットは @morincum/ui で管理(原寸PNG)。設定フッターでの表示幅: 約220-240px

### 7.8 通知デザイン

| 通知 | タイミング | 文言例 |
|---|---|---|
| 引き落とし前日 | 前日18:00(変更可) | 「明日、みずほ銀行から ¥172,000 の引き落とし予定があります」 |
| 契約満了接近 | 3ヶ月前 | 「402号の契約満了まで3ヶ月です。更新の準備をしましょう」 |
| イベント期日 | 期日前日 | 「明日: パークサイド代々木 管理組合総会」 |
| 月初の家賃確認 | 月初(任意ON) | 「先月分の家賃入金を確認しましょう」 |

すべてローカル通知(サーバー不要)。iOS予約上限64件のローリング運用(P-03)。

### 7.9 入力面の3層原則【v0.2】

| 層 | 対象 | 基準 |
|---|---|---|
| ポップアップ(モーダル) | 収支記録・経緯追記・月次確認 | 高頻度・単発・1分以内で完了 |
| 専用画面(unit詳細ハブ) | 物件情報・契約・ローン・定期支出・評価額 | 低頻度・構造的。一度入れたらめったに変えない |
| 設定タブ | 口座・タグ・通知・表示・プラン・アーカイブ | アプリ横断のみ。**物件固有の項目は置かない** |

登録ウィザードは最小3問に留め、詳細はunit詳細の各セクション(未入力バッジ)から後入力させる。「最初に全部聞かない・入口は常に見える」を原則とする。
